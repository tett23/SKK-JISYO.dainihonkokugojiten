# ndlocr-lite の CoreML 実行プロバイダーの試行の経過（2026年9月28日）

いつの時点で何を試したかの記録。結果のまとめは [ocr-coreml.md](ocr-coreml.md) を参照。
時刻は日本時間。環境は Apple M1 Max、ndlocr-lite 1.0.0、onnxruntime 1.23.2。

| 時刻            | 試したこと                                                                                                                             | 結果                                                                                                                                                                                                                                                                                                                                |
| --------------- | -------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 14:03           | ndlocr-lite の環境を調べた                                                                                                             | onnxruntime 1.23.2 に `CoreMLExecutionProvider` がある。推論はレイアウト検出 DEIM（`deim.py`）と文字認識 PARSeq（`parseq.py`）の 2 種類で、どちらも `--device` は cpu か cuda しか選べない                                                                                                                                          |
| 14:04〜14:14    | 各モデルを単体で、CPU と CoreML の 5 通りの設定（NeuralNetwork、MLProgram の ALL・CPUAndGPU・CPUAndNeuralEngine）で計測した            | DEIM は CoreML ではどの設定でも失敗した（MLProgram はモデルを作れず、NeuralNetwork は推論で失敗）。PARSeq（30 文字）は CPU 14 ms に対して CoreML 23〜74 ms、PARSeq（100 文字）は CPU 50 ms に対して NeuralNetwork 198 ms と、CoreML のほうが遅い。CoreML へのモデルの変換に 1 モデル 10〜130 秒かかり、残りの設定は計測を打ち切った |
| 14:15〜14:16    | DEIM の入力のバッチ次元 N を 1 に固定して（`add_free_dimension_override_by_name`、`RequireStaticInputShapes`）CoreML で計測した        | 動くようになった。MLProgram の ALL で 157 ms、CPUAndGPU で 140 ms、NeuralNetwork の CPUAndGPU で 1,162 ms（CPU は 381 ms）                                                                                                                                                                                                          |
| 14:17           | DEIM だけを CoreML（MLProgram、CPUAndGPU、変換結果をキャッシュ）で動かすラッパーを書き、ndlocr-lite 本体を変えずに実行できるようにした | —                                                                                                                                                                                                                                                                                                                                   |
| 14:18〜14:21    | 20 ページ（954646 の R0000200〜R0000219）を ndlocr-lite そのまま（CPU）と、ラッパー（GPU）で OCR した                                  | CPU 58.3 秒、GPU 55.9 秒（初回、変換を含む）、44.0 秒（2 回目、変換済み）                                                                                                                                                                                                                                                           |
| 14:21           | 両方のテキストを比べた                                                                                                                 | 20 ページすべてが違った。R0000200 は CPU の 302 行に対して GPU は 228 行で、行を取りこぼしていた                                                                                                                                                                                                                                    |
| 14:22           | R0000200 で DEIM の出力を CPU と CoreML で直接比べた                                                                                   | スコアの差は CPUOnly で最大 0.00015、CPUAndGPU で 0.27、ALL で 0.32。スコア 0.2 以上の検出は CPU 407 件に対して CPUOnly 407 件（すべて一致）、CPUAndGPU 469 件（一致 313 件）。GPU は計算の精度が下がって検出が変わる。速さは CPUOnly 297 ms、CPUAndGPU 138 ms、CPU 391 ms                                                          |
| 14:23〜14:26    | 結果を変えない CoreML の CPUOnly で 20 ページを OCR し、CPU をもう一度計測した                                                         | CPUOnly 54.4 秒でテキストは CPU と完全に同じ。CPU は 56.2 秒（1 回目と同じ結果）。差は約 3〜7% で、計測のばらつきと同じ程度                                                                                                                                                                                                         |
| 14:26〜14:27    | CPU のまま、20 ページを 10 ページずつ 2 プロセスで同時に OCR した                                                                      | 50.7 秒で、テキストは同じ。1 プロセスでは CPU を 10 コア中 6 コアほどしか使っていない                                                                                                                                                                                                                                               |
| 14:27           | 4 ページを cProfile で計測した                                                                                                         | 1 ページあたり文字認識 約 1.9 秒、レイアウト検出 約 0.5 秒（推論 0.39 秒）、読み順の推定 約 0.2 秒。時間の大半は CoreML で速くならない文字認識にかかる                                                                                                                                                                              |
| 14:28           | 採用しないと判断し、結果を [ocr-coreml.md](ocr-coreml.md) にまとめた                                                                   | GPU は結果を変え、結果を変えない設定はほとんど速くならない                                                                                                                                                                                                                                                                          |
