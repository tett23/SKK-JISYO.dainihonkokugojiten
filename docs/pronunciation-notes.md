# 発音の注記を拾う試行（2026年10月5日）

底本は、読みの仮名の右肩に小さな片仮名で実際の発音を添えることがある（たいふ の い に ュ、ふ に ウ で たゆう。じふ の ふ に ユッ で じゅっ）。
OCR（ndlocr-lite、NDL 側 OCR）はこの注記を読まないので、大夫客（たゆう）、十手（じって）のように見出しを決められない。
注記を画像から拾えるかを試した。**結論として、注記の位置は拾えるが、中身を読み分ける方法はまだ実用にならない。** 辞書の作成には組み込んでいない。

## 注記の位置を拾う

見出しの列の上端から、読みの字数ぶんの高さを切り出し、列ごとの墨の量から読みの列（幅約 30px）の右端を決める。
その右の、隣の列（前の見出しの語釈。幅 8px 以上の墨の多い列）までの帯にある小さな連結成分（高さ 18px 以下、幅 15px 以下、読みの列から 14px 以内）を注記とする。
読みの列に接した注記を切り離すため、読みの列の右端から 2px の位置で墨を切る。
注記の高さから、読みの何字目の傍かを決める（1 字 28px、区切り "-" 13px として数える）。

紙面と照合すると、注記は 字音（せう の せ に シ、たう の た に ト）、ハ行転呼（こひ の ひ に イ）などにも広く付いている。
検証済みの見出しから無作為に選んだ 300 件のうち、約 80 件で注記らしい成分が見つかった（隣の列の字の切れ端を含む）。

## 中身を読む

| 方法                                                       | 結果                                                                                    |
| ---------------------------------------------------------- | --------------------------------------------------------------------------------------- |
| ndlocr-lite（紙面全体の流れ）に注記の帯を渡す              | レイアウト検出が行を見つけず、何も出ない                                                |
| ndlocr-lite の文字認識（PARSeq）に注記の切り出しを直接渡す | 1〜2 字の小さな片仮名は読めず、数字や記号の列になる（縦長・横長・二値化を変えても同じ） |
| macOS の Vision（`VNRecognizeTextRequest`、日本語）        | 注記だけでも、読みの列ごとでも、何も出ない                                              |

汎用の OCR では読めないので、必要な区別に絞って画像の特徴で判定した。

### 大夫（たいふ / たゆう）

い の傍に ュ（低く横長の成分、高さ 12px 以下・幅 6px 以上）があれば たゆう、無ければ たいふ とする。
表記に 大夫・太夫 を含み、読みに たいふ を含む 53 件を全数、紙面と照合した。

| 紙面              | 判定 たゆう | 判定 たいふ |
| ----------------- | ----------: | ----------: |
| ュ あり（たゆう） |          37 |           3 |
| ュ なし（たいふ） |           0 |          13 |

正しい判定は 50 / 53。誤りの 3 件（大夫狂、大夫史、脇太夫）はどれも ュ を見落としたもので、たゆう を たいふ と誤った方向はない。
官名（御史大夫、光祿大夫、中大夫 など）には注記が無く たいふ、芸能・身分（淨瑠璃太夫、大夫客、大夫髷 など）には注記があって たゆう で、語の意味とも合う。

なお、今の辞書では 53 件中 32 件の見出しが たいう になっている（右近大夫 うこんのたいう）。
漢語の記号が無い見出しで たいふ の ふ をハ行転呼として う にしたためで、たゆう・たいふ のどちらでもない。注記とは別に直す必要がある。

### 十（じふ + 清音: じゅう / じっ）

ふ の傍の注記が ウ なら じゅう、ユッ なら じゅっ（じっ）。表記に 十 を含み、読みに じふ と清音が続く 89 件を紙面で見ると、35 件が ユッ だった（十手、十戒、十干、十哲、十指、十挺立 など）。
次の判定を試したが、どれも実用にならなかった。

| 方法                                              | ユッ を ユッ と判定 | ウ を ユッ と誤判定 |
| ------------------------------------------------- | ------------------: | ------------------: |
| 注記の成分の高さ（2 字分なら ユッ）               |              5 / 35 |              0 / 54 |
| 注記の直下に ッ の墨があるか                      |             18 / 35 |             15 / 54 |
| 縮小した形の最近傍（一つ抜きで評価）              |        正解 63 / 80 |                     |
| ッ と ウ の型との照合（型は同じ 89 件から取った） |             35 / 35 |             21 / 54 |

ユ と ッ は 1 字の高さに収まるほど小さく、成分が ウ とほぼ同じ大きさになる。読みの字の位置の推定（1 字 28px）も数 px ずれるので、ッ の有無を位置から決められない。

## 今後の候補

- 注記の切り出しに人（または AI）がラベルを付け、小さな分類器を学習する。必要な区別は ュ・ウ・ッ・イ・ワ など数種類に限られる
- 読みの列の字を 1 字ずつ切り分けて（今は 1 字 28px の推定）、注記の位置を字に正確に対応させる
- 大夫 の判定（50 / 53）は、たいう の誤りを直すのと合わせて組み込める。組み込むには、紙面画像から注記を取り出した結果を `data/` に保存して入力に含める工程が要る（CI は紙面画像を持たない）
