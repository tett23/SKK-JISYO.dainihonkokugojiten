# 未検証の見出しを検証済みに移す方策の検証（2026年10月5〜6日）

未検証辞書（`SKK-JISYO.dainihonkokugojiten.unverified`）の見出しを、検証済みの辞書に移せるかを方策ごとに試した。
作業はブランチ `feature/unverified-promotion` で、7 時間の期限を区切って行った（2026年10月5日 23:47〜10月6日）。

方策ごとに、新たに検証済みになった見出しから無作為に抜き取った（`scripts/draw_promoted.ts`）。それを紙面の切り出しと照合して判定した。
抜き取りの条件（`sample.json`）は、判定の前にコミットした。
判定の一覧は `docs/accuracy/promote-*`（方策で移った見出し）と `docs/accuracy/tier-*`（未検証のまま残った層）にある。
判定は AI（Claude）が紙面の画像と照合して行った。人は確認していない。

比べる基準は、v1.0.11 の L 除外辞書の正解率 99.6%（1992 / 2000、95% 信頼区間 99.2%〜99.8%）。
抜き取り 100 件で誤りが 0 件でも、95% 信頼区間の下限は約 96.3% にとどまる。100 件の抜き取りでは、99% 以上かどうかまでは言えない。

- 既定の規則として採用した方策で検証済みになった見出しの抜き取りは、方策ごとに 96〜100%。全体では 1,219 / 1,225 が正しかった（過去の判定と照合した数）。

#### KANJIDIC2

KANJIDIC2（EDRDG、CC BY-SA 4.0）の音訓を、Unihan の kJapanese に足した。
誤りの 4 件のうち、茅生 かやう と 栗生 くりう は 生 の接尾の読み（-う）によるものだった。1 字の読みで接頭・接尾の印（-）が付くものは採らないことにした。
次のものも、対応付けを素通りさせるので採らない。

- 連濁した形の訓（造 -づくり、立 -だて）
- ぢ・づ で始まる訓（尽 -づく）
- 清音の形がある濁音の音読み（登 ドウ）

これらを採ると、連濁・清濁の検査（`requireAgreement`）を素通りしてしまう。
名乗り（人名の読み）も足すと、検証済みの見出し 425 件が変わったので足さない（`KANJIDIC_NANORI=1` で試せる）。

KANJIDIC2 を足すと、ほかに 2 つの副作用が出た。どちらも直した。

- 字の読みの学習（`learnReadings`）で根拠の語が減り、学習しなくなる読みが出た（小鐵 こがね の 鐵 がね）。学習は、KANJIDIC2 を足す前と後の両方で行って合わせる。
- 開始時点で検証済みだった 66 件が未検証に外れた。上の 2 つの直しで 0 件になった。

#### 形容詞・動詞

形容詞は、文語の終止形（〜し）を現代の形（〜しい・〜い）と SKK の見出しにする。シク活用は あらあらし → あらあらしい、ク活用は たかし → たかい とする。
活用の種類が読めない見出しは、語尾（〜なし・〜にくし・〜がたし など）でク活用と分かるものだけを扱う。
最初の抜き取りの誤り 2 件は、驚 おどろかi と 匂 におわi だった。動詞の未然形の語幹を形容詞として扱っていた。上の制限で除いた。

動詞は、語幹の最後の字を、五段動詞の訓の語幹でも対応付けるようにした（退 のく → の、著 つく → つ）。
複合動詞（惘惑 あきれまどふ、逃退 にげのく）が通るようになった。

#### 連濁・半濁点の検査を緩める

連濁・半濁点の検査は、OCR の二系統が同じように濁点を誤読する例（わか-ばえ 若生、紙面は わか-はえ）から入れたものだった。
その誤読は、同じエンジン（ndlocr-lite）の紙面全体と見出しの読み直しが同じ切り出しから読む場合に起きる。
別のエンジン（ndlocr-lite の紙面全体と NDL 側 OCR）の読みが濁音の字まで一致する候補では、検査を課さないことにした。
連濁で 765 件、半濁点で 488 件が移り、抜き取り各 100 件に誤りは無かった。

#### Wiktionary

英語版 Wiktionary の日本語の項目を、kaikki.org（Wiktextract）が抽出したもの（CC BY-SA 4.0）を使う。
漢字の見出しの読み（ruby）と歴史的仮名遣い（hiragana・historical）を、JMdict と同じ形にして照合に足した（`src/wiktionary.ts`）。
JMdict に無い古語（ひめもす 終日、かんなり 雷鳴、ふもだし 絆）が通るようになった。
古い仮名遣いの読みにも、現代の読みが対応するようになった（こく-くわい 國會 → こっかい、てん-わう 天皇 → てんのう）。
文語の形容詞（あらあらし）は、JMdict の品詞の形に合わないので除く。
字ごとの清濁の統計（`readingStats`）には入れない。入れると、統計の外れで未検証になる見出しが 31 件増えた。

#### OCR の読み直し（未検証すべてを列全体で）

これまで列全体の読み直し（`recheck --full`）は、系統間で一致しない候補だけを対象にしていた。
今回は、未検証の見出しすべて（4 巻で約 3 万件）を対象にした（`deno task recheck --full --all-unverified --status unverified <pid>`）。
2 プロセスで約 4 時間かかった（1 プロセスあたり約 0.9 件/秒）。

読み直しの結果は、2 通りに使う。

1. 系統間の一致の数え上げに加える（これまでどおり）。
2. 照合の最後の候補として試す（新規）。ほかの候補で照合できなかったときと、対応付けでしか通らなかったときに試し、後者は L・JMdict に載る場合に限る。字数の違う読みは使わない（列の切り出しで字が落ちる。心字池 しんじ-の-いけ を しんじいけ と読んだ）。

最初の抜き取り（954647・954645・954646、各 100 件）では、誤りが 7 件あった。
そのうち 3 件（蕞爾 を 最爾、珠璣 を 珠機、絹緞 けんとん を けんどん）は、同じ原因だった。読み直しから採った読み・表記が、その読み直し自身との一致で系統間の一致を満たしていた。
読み直しから採った候補では、読み直しを一致の数に入れないようにした。
直した後の 4 巻の抜き取りは、残った 335 件のうち 331 件が正しかった（98.8%）。

残る誤りの 4 件は、どれも同じエンジンの二系統（紙面全体と列全体の読み直し）が同じように誤読したものだった。

- 屯所 とんしょ を どんしょ
- 占方 せんぱう を せんばう
- 身軀 を 身嫗
- 濃 こき を ころ

NDL 側 OCR が一致しないときに列全体の読み直しを数に入れない試行（`STRICT_D=1`）もした。
610 件が検証済みから外れ、そのうち判定済みのものは正しい 136 件と誤り 2 件だった。失うものが大きいので採らない。

#### 表記を字ごとに比べる

表記が 2 系統以上で一致しない層（`align-single-notation`）の多くは、1 字だけが系統ごとに違っていた（盆荒男子 / 益荒男子）。
字ごとに比べて、各字が 2 系統以上で一致するか、ほかの系統の字では読みに合わなくなる（誤読と言える）場合に決める試行をした。
抜き取りは 3 回行い、誤りの形を見つけるたびに条件を絞った。

- 1 回目は 98 / 100。表記の字が欠けたもの（篤 / 篤癃）と、連濁で読める別の字（白重藤 / 白重籐）が誤りだった。
- 2 回目は 49 / 50。1 字の表記（亞 / 啞）が誤りだった。
- 3 回目は 97 / 100。

それでも、同じ音符の字は残った（酒醺 を 酒燻、香緂 を 香淡、藺屐 を 藺履）。読みでは見分けられないので、基準の 99.6% に届かない。
試行の環境変数（`RELAX_NOTATION=1`）のまま残し、既定にはしない。

#### 清濁で割れた層

濁点・半濁点だけで割れて決まらない層（`voicing-ambiguous`、3,206 件）から 100 件を抜き取り、紙面と照合した（`tier-voicing`）。
判定できた 96 件のうち、今の見出しが正しいのは 83 件（86%）だった。
どの系統の濁点に従えば正しくなるかも数えた。

| 従う濁点                       | 96 件中の正しい数 |
| ------------------------------ | ----------------: |
| NDL 側 OCR                     |                64 |
| 見出しの読み直し               |                77 |
| ndlocr-lite（紙面全体）        |                35 |
| 字ごとの多数決                 |                84 |
| 今の見出し（どれにも従わない） |                83 |

どの系統に従っても 86〜88% にとどまる。この層は規則では移せない。

## 残った未検証の層の正しさ

方策を試した後の未検証から、層ごとに抜き取って紙面と照合した。

| 層                                        |   件数 | 判定（正しい / 抜き取り） | 一覧            |
| ----------------------------------------- | -----: | ------------------------: | --------------- |
| 表記の一致不足（`align-single-notation`） |  3,708 |                   48 / 50 | `tier-notation` |
| 読みの一致不足（`align-single-reading`）  |  1,064 |                   41 / 50 | `tier-reading`  |
| 理由なし                                  | 21,620 |                   23 / 49 | `tier-none`     |
| 清濁で決まらない（`voicing-ambiguous`）   |  3,206 |                   83 / 96 | `tier-voicing`  |
| ぢ・づ（`align-dzi`）                     |    121 |            117 / 121 全数 | `tier-dzi`      |

件数は、抜き取った時点（連濁の緩和の後、OCR の読み直しの取り込みの前）のもの。

- 表記の一致不足は 96% が正しい。ただし誤りは、別の字と見分けられないもの（公益 を 鴻益、絳紗 を 降紗）だった。規則で残りを見分けることは難しい。
- 理由なしは半数が誤りだった。まれな字の誤読（烏草樹 を 鳥草樹、地楡 を 地喩）、字の欠け（季御讀經 を 手御讀經）、読みの誤読（うは-おほめ を つはおほめ）が多い。辞書にも音訓にも合わないので、規則では正誤を決められない。
- ぢ・づ は 97% が正しい。誤りの 4 件は、字音が じ の字（痔、地）を ぢ のまま残したもの（あなぢ 穴痔、きんだみぢ 金彩地、もくれんぢ 木蘭地）と、読みの誤読（うろ-づ、紙面は うろ-くづ）だった。づく（〜尽く）は現代仮名遣いで ずく も許されるので、正しいとした。

清濁の統計で外れた層（`voicing-stats`、134 件）も全数を判定しようとした。しかし、紙面の切り出しの解像度では ば と ぱ を見分けられなかった。判定はしていない。

## AI による全数判定の取り込み（試行）

紙面と照合して正しいと判定した未検証の見出しを、そのまま検証済みに移す仕組みを作った（`src/judged.ts`、`JUDGED=1`）。
判定は、候補の id・SKK の見出し・表記の組に付けて、`docs/accuracy/*/*.tsv` から読む。見出しや表記が判定の後に変わった候補には使わない。
今ある判定で 892 件が移る。

ただし、これは判定した見出しを 1 件ずつ移すだけで、規則ではない。
同じことを未検証の 3 万件すべてに行うには、紙面の切り出しを 3 万件、目で照合する必要がある。今回の抜き取りの速さ（100 件で数分）なら、数十時間かかる。
誤判定の割合（判定者の誤り）も測っていない。人の確認と組み合わせる前提で、試行の環境変数のまま残す。

## 中間の辞書（今回は作らない）

未検証辞書と検証済み辞書の間に、正しい見込みの高い層だけを集めた辞書を置く案もある。
上の抜き取りで、未検証の層の正しさは大きく違った。

- 表記の一致不足、ぢ・づ は 96〜97%
- 清濁で決まらない、読みの一致不足は 82〜86%
- 理由なしは 47%

表記の一致不足（約 3,500 件）とぢ・づ（約 100 件）を「準検証済み」として分ければ、未検証辞書を使うより誤りがずっと少ない。
ただし、どちらも基準の 99.6% には届かない。辞書を一つ増やすと、利用者がどれを入れるか選ぶ手間も増える。
今回は作らず、案として記録する。

## 考察

- **効いたのは、検証の根拠を増やす方策だった。** 辞書（KANJIDIC2、Wiktionary）、活用の扱い（形容詞・動詞）、OCR の系統（列全体の読み直し）を増やした。いずれも、正しい見出しが根拠が足りずに未検証になっていた分を移した。抜き取りの正しさは 96〜100% で、基準に近い。
- **検査を緩める方策は、緩める条件が誤りの原因と結び付いているときだけ効いた。** 連濁・半濁点の検査は、同じエンジンの二系統の誤読を防ぐためのものだった。別のエンジンの一致を条件にすると、誤りを増やさずに緩められた。表記の字ごとの比較は、誤りの原因（同じ音符の字）を条件で除けず、基準に届かなかった。
- **固有名詞の辞書は逆効果だった。** JMnedict の地名の読みは清濁や読みが一般語と違い、OCR の誤読に「辞書の裏付け」を与えてしまう。辞書を足すときは、その辞書の語が底本の語と同じ種類かを確かめる必要がある。
- **OCR の読み直しは、件数の割に効果が小さい。** 3 万件を約 4 時間かけて読み直して、移ったのは 1,128 件（4%）だった。同じエンジンの読み直しは、紙面全体の OCR と同じ誤読をしやすい。別のエンジンの系統を増やすほうが、系統間の一致の意味が強い。
- **残った未検証の大半は、規則では救えない。** 理由なしの層（約 2 万件）は半数が誤りで、まれな字の誤読と字の欠けが多い。これを移すには、人か AI が紙面と 1 件ずつ照合するしかない。今回作った判定の取り込み（`JUDGED=1`）がその受け皿になる。

## 再現

```bash
deno task recheck --full --all-unverified --status unverified 954645 954646 954647 954648
deno task cleanse
```

試行の環境変数は次のとおり。どれも既定では無効。

| 環境変数            | 内容                                                 |
| ------------------- | ---------------------------------------------------- |
| `RELAX_NOTATION=1`  | 表記を字ごとに比べて決める                           |
| `JUDGED=1`          | 紙面と照合して正しいと判定した見出しを検証済みに移す |
| `JMNEDICT=<パス>`   | JMnedict（など JMdict 形式の辞書）を照合に足す       |
| `KANJIDIC_NANORI=1` | KANJIDIC2 の名乗りも足す                             |
| `KANJIDIC=0`        | KANJIDIC2 を使わない                                 |
| `WIKTIONARY=0`      | Wiktionary を使わない                                |
| `FULL_OPTIONS=0`    | 列全体の読み直しの読み・表記を照合の候補にしない     |
